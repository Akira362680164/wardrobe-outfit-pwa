# 全入口协议主动同意整改设计

## 目标

消除 Android App、衣橱 Web App 与微信小程序认证入口中的默认自动同意行为。所有真正发起登录、注册或注册验证码请求的入口，都必须由用户主动勾选《用户服务协议》和《隐私政策》后才能继续。

Wardora 合规官网当前没有登录或注册入口，本次保持不变。

## 平台与入口范围

### Android App 与衣橱 Web App

两端共用 `src/components/auth/auth-gate.tsx`：

- 账号密码登录。
- 邮箱注册。

### 微信小程序

- 登录首页的微信登录/注册。
- 邮箱或手机号密码登录。
- 邮箱注册，包括发送邮箱验证码和提交注册。

忘记密码属于既有账号恢复流程，不新增协议勾选。仅进入密码登录页或邮箱注册页的导航按钮不发起认证或个人信息处理请求，不要求在登录首页重复勾选；目标页面会在真正提交前独立要求用户确认。

## 交互规则

1. 每个认证页面首次进入时，协议复选框必须默认未勾选。
2. 固定文案为“我已阅读并同意《用户服务协议》和《隐私政策》”。
3. 《用户服务协议》和《隐私政策》分别可点击打开现有法律内容页。
4. 打开或阅读法律内容不能自动勾选复选框；返回后保留当前页面内原有选择状态。
5. 用户取消勾选后，认证入口立即恢复未同意状态。
6. 勾选状态只存在当前页面内存，不写入本地持久存储，不跨页面自动继承。

## 按钮与错误状态

- 表单必填项未完成时，主按钮沿用现有禁用状态。
- 表单必填项已完成但协议未勾选时，主按钮保持低饱和/灰色视觉，但仍允许点击以提供原因反馈。
- 未勾选时点击认证按钮，不调用登录、注册、微信授权或验证码接口；在当前页面显示红色提示：

  `请先阅读并同意《用户服务协议》和《隐私政策》`

- 不使用 Toast、系统弹窗或自动勾选。
- 协议已勾选且其他输入有效时，主按钮使用现有 Wardora 蓝色主操作样式并允许提交。
- 用户勾选协议后清除仅由“未同意协议”产生的红色提示；其他表单或网络错误按现有规则保留或更新。

微信登录首页没有表单字段，因此其“微信登录/注册”按钮只由提交中状态和协议勾选状态决定视觉；未勾选时仍可点击并显示页面内红色提示。

## 状态与数据流

### App / Web

登录表单状态新增 `accepted` 布尔值，初始为 `false`。注册表单复用现有 `accepted` 字段。`AuthGate` 在调用认证 API 前执行最终防线校验，表单组件负责复选框、按钮视觉和页面内错误呈现。

### 微信小程序

微信登录页、密码登录页和邮箱注册页各自维护 `accepted: false`。对应事件处理器在任何网络请求前检查该字段；失败时只更新本页 `errorMessage`。页面不使用本地存储、全局变量或跨页 query 参数传递同意状态。

## 无障碍与触摸

- App / Web 使用原生 checkbox，并保持可点击 label 关联。
- 小程序使用明确的可触摸复选控件，选中与未选中状态同时通过图形和可读文案表达。
- 协议链接的点击区域与复选框切换互不干扰，点击链接不会误切换同意状态。
- 360px 宽度下协议文案允许自然换行，不得横向溢出或遮挡按钮。

## 验证与交付

### 自动验证

- 为 App / Web 登录与注册补充回归测试：默认未同意、未同意不调用 API、红色固定错误文案、勾选后允许调用。
- 为小程序三个认证页面补充合同测试，确认每个网络入口都有 `accepted` 前置校验，且旧的“继续即代表同意”“登录代表认可”文案已移除。
- 运行 App / Web typecheck、相关认证逻辑测试与生产构建。
- 运行小程序 typecheck、认证逻辑测试和微信开发者工具编译。

### 实际交互验证

- App 以手机竖屏验证默认未勾选、链接打开/返回、未勾选红色提示、勾选后的按钮状态和正常提交入口。
- 改动进入 Android APK，因此递增应用版本，使用固定 `CN=fangzheng` 签名构建 APK，并在 Android 模拟器验证启动、登录页、返回键和严重错误日志。
- 小程序在微信开发者工具模拟器检查微信登录、密码登录和邮箱注册三个页面。
- 本次不上传体验版、不发布小程序、不部署官网或生产服务。

## 非目标

- 不修改协议和隐私政策正文。
- 不给 Wardora 合规官网新增登录或注册功能。
- 不改变服务端认证契约、账号数据结构、登录会话或隐私数据存储策略。
- 不将一次同意保存成长期偏好，也不以阅读协议页面代替主动勾选。
